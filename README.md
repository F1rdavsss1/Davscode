# DavsCode

Сайт-портфолио, приём заявок, Telegram-бот с CRM и синхронизация с Google Sheets.

**Стек:** Next.js 16 (App Router, TypeScript), Zod, Telegram Bot API, Google Sheets API, Vercel.

> **Временный режим хранения.** Пока нет сервера с базой, все данные хранятся в Google-таблице. Схема PostgreSQL для будущего переезда лежит в `db/schema.sql`.

## Как устроено

```
Сайт (форма) ─┐                          ┌─► Telegram владельцу (уведомление + кнопки)
              ├─► Google Sheets «Заявки» ┤
Бот (бриф) ───┘   (источник правды)      └─► повтор уведомления при сбое (cron / следующий запрос)
```

Листы таблицы:

| Лист | Что там |
| --- | --- |
| «Заявки» | Одна строка на заявку, колонки по ТЗ 12.2. A–U — для человека, **V (скрыта)** — служебная копия заявки, по ней система читает данные |
| «Аналитика» | Формулы по заявкам |
| «Журнал» (скрыт) | Кто, когда и что сделал с заявкой: создание, согласие, смены статусов, сообщения клиенту |
| «Служебное» (скрыт) | Состояние диалогов бота, связи «сообщение → клиент», лимит частоты заявок |

- Клиент получает «успех» только после того, как строка записана в таблицу. Если Google недоступен — понятная ошибка, данные формы сохраняются в браузере.
- Уведомление владельцу отправляется после ответа клиенту (`after()`), а при сбое повторяется с экспоненциальной задержкой (30 с → … → 6 ч, до 10 попыток). Состояние видно в колонке U («Состояние синхронизации»). Исчерпанные попытки — предупреждение владельцу, команда `/retry` возвращает их в очередь.
- Повтор из-за тайм-аута или двойного нажатия не создаёт дубликатов: заявка ищется по ключу идемпотентности, а после записи система проверяет и убирает дубль, если два запроса пришли одновременно.
- Статусы меняются только кнопками в боте. Права владельца проверяются на сервере при каждом действии, устаревшие кнопки обновляются до актуального состояния.
- Колонку «Заметки» (N) система никогда не перезаписывает. Строка ищется по ID, поэтому сортировка и фильтры не мешают.
- **Не удаляйте строки и не правьте колонку V** — это данные заявки. Ненужную заявку переводите в «Отказ».
- Ограничения временного режима: у Google Sheets нет транзакций и есть квота (~60 запросов в минуту на запись). Для текущего объёма заявок этого достаточно; при росте — переезд на PostgreSQL.

## Структура

| Путь | Что там |

| `src/config/site.ts` | Контакты, услуги, **цены и сроки** — единый источник |

## Локальный запуск

```bash
npm install
cp .env.example .env.local   # заполните GOOGLE_* и TELEGRAM_*
npm run sheets:init
npm run dev
```

**Проверить бота локально** (без деплоя и https): во втором терминале `npm run bot:dev` — скрипт забирает сообщения у Telegram и передаёт их в локальный вебхук. Работает, только пока у бота не установлен production-вебхук. Без Google-ключей разделы бота работают на временном хранилище в памяти, а заявка вернёт «не удалось сохранить».

Без Google-переменных сайт открывается, но заявки не принимаются (их негде сохранить) — форма покажет ошибку и сохранит введённые данные. Без Telegram-переменных заявки сохраняются, а уведомления ждут и отправятся после настройки.

## Развёртывание (Vercel)

1. **Таблица.** Настройте Google Sheets (раздел ниже) и выполните `npm run sheets:init`.
2. **Переменные.** Перенесите все переменные из `.env.example` в настройки проекта Vercel. Сгенерируйте случайные `TELEGRAM_WEBHOOK_SECRET`, `CRON_SECRET`, `IP_HASH_SECRET`.
3. **Деплой.** `vercel --prod` или подключите репозиторий.
4. **Вебхук.** `npm run telegram:webhook` (берёт `NEXT_PUBLIC_SITE_URL`, нужен https).
5. **Повторы.** `vercel.json` запускает `/api/cron/jobs` раз в сутки (повтор уведомлений и очистка листа «Служебное») — это ограничение бесплатного тарифа Vercel. Повторы также идут при каждом обращении к боту. Для частых повторов настройте внешний планировщик (например, cron-job.org) на `GET /api/cron/jobs` каждые 5 минут с заголовком `Authorization: Bearer <CRON_SECRET>`.

## Telegram-бот

1. Создайте бота у @BotFather, токен — в `TELEGRAM_BOT_TOKEN`.
2. Узнайте свой числовой ID (например, у @userinfobot) и укажите его в `TELEGRAM_OWNER_ID`.
3. Напишите своему боту `/start`, иначе он не сможет присылать вам уведомления.

**Бот и сайт синхронизированы.** Разделы бота «Услуги и цены», «Портфолио» и «Вопросы и ответы» собираются из тех же файлов, что и сайт: `src/config/site.ts` (услуги, цены, сроки), `src/content/cases.ts` (кейсы), `src/content/faq.ts` (вопросы). Поменяли цену или добавили кейс — после деплоя изменения видны и на сайте, и в боте. Бриф в боте использует те же варианты и проверки, что и форма на сайте, а заявки из обоих каналов попадают в одну таблицу с общей нумерацией.

Команды клиента: `/start`, `/services`, `/cases`, `/faq`, `/brief`, `/ask`, `/stop`. Ссылки для сайта и соцсетей открывают нужный раздел сразу: `t.me/<бот>?start=services`, `?start=cases`, `?start=faq`, `?start=case_<slug>`, `?start=brief`.

Команды владельца: `/stats`, `/lead DC-000001`, `/retry [DC-000001]`, `/help`. Чтобы ответить клиенту, ответьте реплаем на его вопрос или на сообщение «Уточнение по #…».

## Google Sheets

1. В Google Cloud создайте сервисный аккаунт, включите Google Sheets API и скачайте JSON-ключ.
2. Заполните `GOOGLE_SERVICE_ACCOUNT_EMAIL` и `GOOGLE_PRIVATE_KEY` (переводы строк — `\n`).
3. Создайте таблицу, дайте сервисному аккаунту доступ **Редактор** (больше никому, публичную ссылку не включайте), ID таблицы — в `GOOGLE_SHEETS_ID`.
4. `npm run sheets:init` создаст листы «Заявки» (заголовки, защита системных колонок предупреждением, скрытая колонка V), «Аналитика» (формулы; в колонке C — как считается каждый показатель), а также скрытые «Журнал» и «Служебное». Скрытые листы открываются через меню «Вид → Скрытые листы».
5. В таблицу не записываются паспортные данные и банковские реквизиты (ТЗ 14.3). Когда появится анкета реквизитов, эти данные будут храниться только на сервере.

## Восстановление после сбоев

- **Не пришло уведомление.** В боте `/stats` покажет число неотправленных уведомлений, в колонке U видно состояние каждой заявки. Исправьте причину (токен, ID владельца) и выполните `/retry`.
- **Форма пишет «Не удалось сохранить заявку».** Таблица недоступна: проверьте `GOOGLE_*`, доступ сервисного аккаунта (роль «Редактор») и квоты в Google Cloud Console.
- **Бот молчит.** `npm run telegram:webhook` покажет адрес вебхука и последнюю ошибку Telegram.
- **Резервные копии.** Google хранит историю версий таблицы («Файл → История версий»). Дополнительно раз в неделю делайте копию книги («Файл → Создать копию») — история версий не защищает от удаления файла.
