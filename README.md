# DavsCode

Сайт-портфолио, приём заявок, Telegram-бот с CRM и синхронизация с Google Sheets.

**Стек:** Next.js 16 (App Router, TypeScript), PostgreSQL (`postgres`), Zod, Telegram Bot API, Google Sheets API, Vercel.

## Как устроено

```
Сайт (форма) ─┐                      ┌─► Telegram владельцу (уведомление + кнопки)
              ├─► PostgreSQL ─► jobs ┤
Бот (бриф) ───┘   (источник правды)  └─► Google Sheets «Заявки» (одна строка на заявку)
```

- Заявка сохраняется в базе **в одной транзакции** с согласием и заданиями на доставку. Клиент получает «успех» только после записи в базу.
- Уведомление и синхронизация выполняются после ответа клиенту (`after()`), а при сбое повторяются с экспоненциальной задержкой (30 с → … → 6 ч, до 10 попыток). Исчерпанные задания получают статус `failed`, владельцу приходит предупреждение, команда `/retry` возвращает их в очередь.
- Повторы из-за тайм-аута или двойного нажатия не создают дубликатов: ключ идемпотентности уникален на уровне базы.
- Статусы меняются только кнопками в боте. Права владельца проверяются на сервере при каждом действии, переход атомарен (`where status = ожидаемый`), устаревшие кнопки обновляются до актуального состояния. Все изменения пишутся в `lead_events`.
- В Google Sheets колонка «Заметки» (M) системой никогда не перезаписывается. Строка ищется по ID, поэтому сортировка таблицы не мешает.

## Структура

| Путь | Что там |
| --- | --- |
| `src/config/site.ts` | Контакты, услуги, **цены и сроки** — единый источник |
| `src/content/cases.ts`, `faq.ts` | Кейсы портфолио и FAQ |
| `src/lib/leadSchema.ts` | Справочники и схемы валидации (общие для формы, API и бота) |
| `src/lib/leads.ts`, `jobs.ts` | Сохранение заявок, переходы статусов, очередь заданий |
| `src/lib/bot/` | Клиентский бриф и вопросы, админ-кнопки, `/stats` |
| `src/app/api/lead` | Приём заявок с сайта |
| `src/app/api/telegram/webhook` | Вебхук бота |
| `src/app/api/cron/jobs` | Повтор незавершённых заданий |
| `db/schema.sql` | Схема БД (идемпотентная) |

## Локальный запуск

```bash
npm install
cp .env.example .env.local   # заполните DATABASE_URL, остальное — по мере подключения
npm run db:migrate
npm run dev
```

Без Telegram и Google переменных сайт и приём заявок работают: заявки сохраняются, а задания ждут в очереди и доставятся после настройки.

## Развёртывание (Vercel)

1. **База.** Создайте PostgreSQL (Neon, Supabase или Yandex Managed PostgreSQL). Используйте pooled-строку подключения. Выполните `npm run db:migrate` с production `DATABASE_URL`.
2. **Переменные.** Перенесите все переменные из `.env.example` в настройки проекта Vercel. Сгенерируйте случайные `TELEGRAM_WEBHOOK_SECRET`, `CRON_SECRET`, `IP_HASH_SECRET`.
3. **Деплой.** `vercel --prod` или подключите репозиторий.
4. **Вебхук.** `npm run telegram:webhook` (берёт `NEXT_PUBLIC_SITE_URL`, нужен https).
5. **Повторы.** `vercel.json` запускает `/api/cron/jobs` раз в сутки — это ограничение бесплатного тарифа Vercel. Повторы также идут при каждом обращении к боту. Для частых повторов настройте внешний планировщик (например, cron-job.org) на `GET /api/cron/jobs` каждые 5 минут с заголовком `Authorization: Bearer <CRON_SECRET>`.

## Telegram-бот

1. Создайте бота у @BotFather, токен — в `TELEGRAM_BOT_TOKEN`.
2. Узнайте свой числовой ID (например, у @userinfobot) и укажите его в `TELEGRAM_OWNER_ID`.
3. Напишите своему боту `/start`, иначе он не сможет присылать вам уведомления.

Команды владельца: `/stats`, `/lead DC-000001`, `/retry [DC-000001]`, `/help`. Чтобы ответить клиенту, ответьте реплаем на его вопрос или на сообщение «Уточнение по #…».

## Google Sheets

1. В Google Cloud создайте сервисный аккаунт, включите Google Sheets API и скачайте JSON-ключ.
2. Заполните `GOOGLE_SERVICE_ACCOUNT_EMAIL` и `GOOGLE_PRIVATE_KEY` (переводы строк — `\n`).
3. Создайте таблицу, дайте сервисному аккаунту доступ **Редактор** (больше никому, публичную ссылку не включайте), ID таблицы — в `GOOGLE_SHEETS_ID`.
4. `npm run sheets:init` создаст листы «Заявки» (заголовки, защита системных колонок предупреждением) и «Аналитика» (формулы; в колонке C — как считается каждый показатель).

## Восстановление после сбоев

- **Не пришло уведомление / нет строки в таблице.** В боте `/stats` покажет число неудавшихся заданий. Исправьте причину (токен, доступ к таблице) и выполните `/retry`. Детали: `select * from jobs where status = 'failed'`.
- **Бот молчит.** `npm run telegram:webhook` покажет адрес вебхука и последнюю ошибку Telegram.
- **Резервные копии.** Включите автоматические бэкапы/PITR у провайдера БД и периодически проверяйте восстановление в отдельную базу. Повтор заданий — не замена бэкапу.

- [ ] Поля в квадратных скобках в `src/app/privacy/page.tsx`, проверка политики юристом (152-ФЗ, локализация данных, уведомление РКН).
- [ ] Сроки и тексты концептов в `src/content/cases.ts`, реальные скриншоты вместо заглушек.
- [ ] `NEXT_PUBLIC_TELEGRAM_USERNAME`, `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME`; пустые ссылки на сайте скрываются.
- [ ] Рабочие часы в `site.responseNote`.
- [ ] Lighthouse на production-адресе (LCP < 2,5 с, CLS ≤ 0,1, INP ≤ 200 мс).
